# First GitHub Release Set

Status: Draft
Date: 2026-04-26

## Goal

Define the recommended file set for the first public release.

## Recommended release style

Documentation-first release.

This means the first public version should emphasize:
- clarity
- architecture
- schemas
- templates
- examples
- quality guidance

It should not depend on advanced tooling or hidden local context.

## Include in release v0.1

### Root docs
- `README.md`
- `PACKAGE-INDEX.md`
- `PACKAGE-VISION.md`
- `QUICKSTART.md`
- `FIRST-30-MINUTES.md`
- `COMMON-MISTAKES.md`
- `ADOPTION-CHECKLIST.md`
- `ARCHITECTURE.md`
- `ROADMAP.md`
- `SCHEMA-PACK-V1.md`
- `CATEGORY-SCHEMA-PACK-V1.1.md`
- `CATEGORY-TEMPLATES-PACK-V1.md`
- `LINT-PACK-V1.md`

### Supporting directories
- `references/`
- `schemas/`
- `templates/`
- `lint/`
- `onboarding/`
- `examples/`
- `repo/`

## Optional to include in v0.1

- future skill path guidance
- release structure guidance
- consistency checklist

## Do not require for v0.1

- automation scripts
- vector indexing
- platform-specific integration code
- large historical corpora

## Release message guidance

The first release should present the package as:
- a reusable architecture kit
- a documentation-first memory system
- a practical pattern for long-running agents
